# 电商购物车流失与品牌运营优先级项目立项书

## 1. 业务背景

数据记录了 2019 年 12 月的电商行为事件。项目需要回答的不是“哪个品牌一定有问题”，而是：在已经发生加购的会话—商品组合中，哪些品牌同时具有较大的业务覆盖量和较高的移除倾向，值得品牌运营人员优先核查并设计实验。

## 2. 决策对象与使用者

- 决策对象：品牌运营排查和实验优先级。
- 主要使用者：品牌运营负责人、品类运营负责人。
- 作品集使用者：面试官或项目评审者，用于检查业务口径、SQL/Python 实现和交付能力。

## 3. 核心分析问题

1. 首次观测到加购后的 48 小时内，购买、未明确处置和移除分别占多少？
2. 哪些品牌的覆盖量高，同时“移除/购买比”较高？
3. 该排序对 24/48/72 小时时间窗口是否敏感？
4. 当前数据能支持哪些业务判断，哪些判断必须通过补充数据或实验验证？

## 4. 分析粒度与主口径

- 主分析粒度：`user_session × product_id`，一行代表一个会话内某商品的首次观测加购。
- 主时间窗口：首次观测加购后 48 小时。
- 完整样本：只有当数据结束时间覆盖完整的 48 小时观察窗口时，记录才进入主分析。
- 结果优先级：窗口内出现购买记为 A；没有购买但出现移除记为 C；两者都没有记为 B。
- 品牌优先级：品牌覆盖量和“移除/购买比”共同判断；该比值是描述性运营信号，不是因果风险概率。

## 5. 项目范围

### 范围内

- 数据质量、时间覆盖、粒度和事件顺序检查。
- 事件级、用户级、会话级和会话—商品级指标的区分。
- 48 小时主口径、24/72 小时敏感性分析。
- 品牌覆盖量、购买率、未明确处置率、移除率和移除/购买比。
- SQL 计算、Python 独立复核、Excel/Power BI 展示方案和管理层结论。

### 范围外

- 销售额、利润、毛利、库存、履约、营销成本和真实 GMV 影响；原始数据没有这些字段。
- 将品牌差异解释为因果根因。
- 跨月复购、长期生命周期和历史首次加购；数据只覆盖一个月，且“首次”仅指本数据窗口内首次观测。
- 生产级实时推荐或自动干预系统。

## 6. 交付物

- 项目立项书、数据字典、指标字典、成果清单。
- 只读 SQL 数据检查、指标层和敏感性分析。
- 可从头运行的 Python 验证脚本与正式 Notebook。
- 数据质量报告、核心图表和一页管理层报告。
- Excel 看板及不超过两页的 Power BI 设计/实现。
- README、环境复现说明和面试表达材料。

## 7. 验收标准

1. 原始数据和 PostgreSQL 数据均未被修改。
2. 主指标明确粒度、分母、窗口、排除条件和时区。
3. SQL 与 Python 对关键总量、分组量和品牌指标完成对账。
4. 24/48/72 小时敏感性使用同一批 72 小时完整样本，避免因样本边界变化产生伪差异。
5. 图表、Excel、Power BI 和文字结论引用同一套正式导出数据。
6. 每条管理建议均标注证据、限制以及需要验证的实验，不把相关性写成因果。

## 8. 本轮优化原则

- 保留原 Notebook、旧图表和练习版 Excel/PBIX，作为学习过程证据。
- 新建正式目录和文件，不覆盖旧成果。
- 大表计算优先在 PostgreSQL 中完成；Python 只读取聚合结果和 48 小时中间表。
- 所有数据库访问只读；密码只从本机安全配置或环境变量读取。
