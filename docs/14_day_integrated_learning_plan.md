# 14 天综合学习计划：从项目理解到跨工具交付

## 1. 计划目标

这 14 天的目标不是逐行读完项目中的所有文件，也不是把 SQL、Python、Excel 或 Power BI 中的某一项学到很深，而是建立一套可以迁移到日常数据分析工作的完整能力：

```text
理解业务问题
→ 定义粒度、窗口和指标
→ 用 SQL 正确取数
→ 用 Python 独立验证
→ 用 Excel 完成轻量交付
→ 用 Power BI 做交互展示
→ 完成跨工具对账
→ 讲清证据、限制和建议
```

完成后应当能够：

1. 用自己的话解释项目服务什么决策。
2. 面对一个指标，说明一行是什么、分子分母是什么、观察窗口是什么。
3. 看懂并修改项目中的核心 SQL，不要求从空白页默写全部长 SQL。
4. 从 SQL 结果追溯到 Python、Excel 和 Power BI 中的同一个数字。
5. 完成一页管理层摘要和两页以内的 Power BI 看板。
6. 区分描述性发现、相关关系、原因假设和因果结论。
7. 在面试中诚实说明自己的工作、AI 协作和验证过程。

## 2. 总体时间比例

时间根据每天实际可用时长自由伸缩，以下比例按 14 天总体投入计算：

| 能力模块 | 建议比例 | 当前阶段的目标 |
|---|---:|---|
| 业务问题、指标与结论边界 | 20% | 能定义决策对象、粒度、分母、窗口和限制 |
| SQL | 30% | 掌握筛选、聚合、JOIN、CTE、条件聚合和基础窗口函数 |
| Excel | 15% | 能对账、筛选、汇总并制作一页管理层摘要 |
| Power BI | 15% | 理解数据模型、Measure、筛选上下文和两页看板 |
| Python | 10% | 能从明细重新聚合、检查差异和制作必要图表 |
| 汇报、文档与面试表达 | 10% | 能把证据、影响、限制和建议讲清楚 |

这些比例是整个 14 天的比例，不要求每天把六项技能平均切成很小的时间块。每天采用：

```text
70% 当天主任务
+ 20% 跨工具追溯或验证
+ 10% 不看文件复述与记录
```

这样既能持续深入一个核心问题，又不会连续多天只学习一个工具。

## 6. 每天的学习方式

每个学习主题按以下顺序进行：

```text
1. 先说业务目标，不看代码。
2. 写输入、处理、判断条件、输出和边界情况。
3. 用口头伪代码复述。
4. 再打开 SQL、Python、Excel 或 DAX 对照实现。
5. 只解释最关键的 2—5 行语法。
6. 查看实际结果或抽样记录。
7. 完成至少一个验证检查。
8. 不看文件重新讲一遍。
```

不要求机械默写长代码。可以查文档、使用已有模板和 AI，但必须能够解释：

- 为什么需要这一步；
- 一行代表什么；
- 修改会影响哪些下游结果；
- 如何证明结果没有算错。

## 7. 14 天结束后的验收标准

### 业务与指标

- 能把模糊问题改写成可验证的分析问题。
- 能说明主粒度、窗口、分子、分母和排除条件。
- 不把相关关系或启发式排序写成因果结论。

### SQL

- 能独立写常见的筛选、聚合、CASE WHEN和基础 JOIN。
- 能看懂并修改 CTE 和 `ROW_NUMBER()`等项目常用结构。
- 能分步骤验证行数、唯一键、时间顺序和指标总量。

### Python

- 能读取正式导出、重新聚合并比较差异。
- 能解释为什么模型或指标可能存在泄露、截断或样本偏差。

### Excel

- 能制作或维护管理层总览、品牌明细和质量/对账页。
- 能追溯展示数字到底层正式数据。

### Power BI

- 能区分计算列与 Measure。
- 能理解筛选上下文，并使用分子分母重新计算比率。
- 能完成两页以内、围绕业务问题的基础看板和 QA。

### 表达

- 能用 90 秒讲清项目。
- 能回答粒度、窗口、B 类、品牌覆盖和因果边界等追问。
- 能诚实说明 AI 协助的范围以及自己完成的验证和判断。

## 8. 计划执行原则

- 如果某个 SQL 函数不影响业务理解，先记录，暂不深挖。
- 如果某个口径、JOIN或分母不理解，必须停下来解决，因为它会影响全部下游结果。
- 每两到三天必须出现一次跨工具追溯，避免把工具割裂学习。
- 学习效果用“能否解释、修改、验证和迁移”衡量，不用阅读文件数量衡量。
- 14 天后优先完成当前项目交付和面试表达，不继续堆叠新模型、新图表或新数据集。
