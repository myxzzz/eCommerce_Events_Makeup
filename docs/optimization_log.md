# 企业化优化记录

## 这份记录怎么用

这不是为了否定旧项目。旧 Notebook、图表和模型记录展示了从探索到发现问题的过程；本轮新增的是一条可以复核、复跑和交付的正式链路。正式结论以前置口径、`sql/formal/`、正式导出和跨工具对账为准。

## 优化明细

| 编号 | 原有风险或缺口 | 本轮处理 | 为什么这样处理 | 验证证据 |
|---|---|---|---|---|
| 1 | 业务目标容易写成“找高风险品牌”，但数据不能证明品牌是根因 | 改为“确定品牌运营排查优先级” | 把描述性相关与因果结论分开 | `docs/project_charter.md`、管理层报告 |
| 2 | “人数、用户、会话、商品”在不同分析中可能混用 | 正式主粒度固定为 `user_session × product_id` 的首次观测加购 | 保证分子、分母和 JOIN 键一致 | `docs/metric_dictionary.md`、`06_cohort_detail_48h.sql` |
| 3 | 旧 A/B/C 可能包含加购前事件或超长窗口结果 | 从首次真实 `cart` 起点重建 48 小时窗口 | 保证结果发生在预测/观察起点之后 | `02_kpi_summary_48h.sql` |
| 4 | 月末样本无法完整观察 48 小时 | 只保留 `window_end_time <= source_max_time` 的样本 | 消除右截断造成的伪低转化 | 排除 19,231 个尾部候选 |
| 5 | 同一窗口内既移除又购买时标签可能冲突 | 购买优先：有 `purchase` 归 A；无购买但有移除归 C | 三组互斥且总和等于队列 | A+B+C=772,119；标签矛盾 0 |
| 6 | 字面值 `user_session='NaN'` 可能被 SQL 当成真实会话 | 将 NULL、空串、`nan/null/none` 统一视为无效键 | 防止不同用户事件串到同一伪会话 | 旧 CSV 与正式队列差 369 行的根因已定位 |
| 7 | 字面值 `brand='NaN'` 可能被当作最大品牌 | 占位值标准化为空；品牌榜只统计已知品牌 | 防止品牌排名失真 | 已知品牌覆盖率仅 55.99% |
| 8 | 旧品牌覆盖量可能只使用 A+C | 品牌样本数改为 A+B+C；A+C 指标只作辅助 | B 类占 66.22%，不能从业务规模中消失 | 正式 KPI 与品牌导出 |
| 9 | `C/A risk ratio` 容易被理解为概率或因果风险 | 改名“移除/购买比”，并保留分子分母 | 比值可超过 1，不是概率 | 指标字典与 DAX 均使用新名称 |
| 10 | 固定 1.5 容易被误写成行业标准 | 明确为可调启发式筛选线 | 企业阈值应由干预成本、历史基线或资源容量校准 | 品牌 SQL 注释和管理层限制说明 |
| 11 | 只比较 24/48/72 小时各自可观察样本会改变分母 | 使用同一批完整 72 小时共同队列 | 将窗口变化与样本构成变化分离 | 共同队列 756,116；购买率极差 0.043 个百分点 |
| 12 | 旧模型随机按行切分，且整段 session 特征含事后行为 | 正式交付不使用模型结果作决策证据 | 避免同会话泄露、时间穿越和追求漂亮分数 | README 将模型内容降为历史探索 |
| 13 | 缺少可单独验证的 SQL 中间步骤 | 新增源概况、队列质量、KPI、品牌、漏斗、窗口敏感性和明细 SQL | 便于定位 JOIN 膨胀、标签或分母错误 | `sql/formal/00`—`06` |
| 14 | SQL、Python、Excel 可能各算一套数字 | SQL 产出明细，Python重新聚合；Excel读取同一正式导出 | 跨工具一致性是企业交付的基本要求 | 25 项检查 0 错误；Excel 公式错误扫描 0 |
| 15 | 原始重复行没有处理策略 | 报告 183,860 个业务字段重复超额行，但不自动删除 | 数据无 `event_id`，无法区分技术重复与真实重复事件 | `reports/data_quality_report.md` |
| 16 | 图表多但缺少一页决策结论 | 增加结果构成、品牌优先矩阵、窗口敏感性和管理层行动建议 | 每张图围绕一个决策问题 | `reports/formal_charts/`、管理层报告 |
| 17 | Excel 更像练习文件，缺少管理层入口和质量页 | 新增正式多页工作簿、口径说明、品牌优先级、窗口和对账页 | 让非技术使用者可以筛选、复核和追溯 | `outputs/formal_delivery/eCommerce_brand_priority_formal.xlsx` |
| 18 | Power BI 口径可能直接平均品牌比率 | 提供基于分子分母重算的 DAX 和两页看板规范 | 切片器变化后比率必须在筛选上下文中重算 | `reports/power_bi_measures.dax` |
| 19 | 缺少环境、凭据和执行顺序说明 | 固化解释器、依赖、只读 SQL 顺序和环境变量规则 | 降低“只能在作者电脑运行”的风险 | `docs/environment_and_reproduction.md` |

## 本轮没有做、也不应该假装完成的内容

- 没有把品牌差异写成库存、运费、促销、口碑或商品质量的根因；数据中没有这些字段。
- 没有新增机器学习模型；当前最重要的是修复口径、数据泄露和交付链路。
- 没有自动删除重复事件；缺少稳定 `event_id`，删除依据不足。
- 没有新建正式 PBIX；当前机器未发现 Power BI Desktop。已保留旧 PBIX，并交付数据、DAX、页面规范和 QA 清单。
- 没有修改 PostgreSQL 数据，也没有覆盖旧 Notebook、旧 Excel 或旧图表。

## 企业里下一轮最有价值的工作

1. 把优先品牌下钻到 SKU，检查贡献集中度和最小样本量。
2. 补充库存、促销、运费、渠道、设备和结账错误日志，形成可验证的机制假设。
3. 增加跨月份或滚动窗口数据，验证品牌排序稳定性。
4. 在 Power BI Desktop 中按规范完成两页看板，并逐项执行切片器 QA。
5. 如要做干预，先设计实验与护栏指标，再讨论因果效果。
